---
title: Quickstart
description: Start omni-model with PostgreSQL and configure your first safe client request.
---

omni-model runs as one application container backed by PostgreSQL. The dashboard handles
authentication, provider credentials, routing, limits, and publishable keys, so you do not need to
write a configuration document to get started.

<Steps>
  <Step title="Start the local stack">
    Clone the repository, build the image, and generate two stable development secrets:

    ```sh
    git clone https://github.com/tiepvuvan/omni-model.git
    cd omni-model
    docker build -t omni-model:local .

    printf 'OMNI_ADMIN_SECRET=%s\nOMNI_ENCRYPTION_KEY=%s\n' \
      "$(openssl rand -base64 32)" \
      "$(openssl rand -base64 32)" > examples/.env

    docker compose \
      --env-file examples/.env \
      -f examples/docker-compose.dashboard.yml \
      up -d --wait
    ```

    PostgreSQL and dashboard data live in a named volume, so a normal restart keeps your setup.
  </Step>
  <Step title="Create the first operator">
    Open [http://localhost:8787/admin](http://localhost:8787/admin). The sign-up screen is available
    only while the database has no accounts; that first account becomes an administrator.
  </Step>
  <Step title="Configure protection and routing">
    In the dashboard:

    1. Choose one user authentication method.
    2. Add app verification for the client platforms you ship.
    3. Add a model-routing rule and provider credential.
    4. Set input, concurrency, prompt-cache, and per-user token limits.
    5. Generate a publishable key for your client.

    Changes validate and apply immediately. You do not need to restart the container.
  </Step>
  <Step title="Make a request">
    Use the publishable key as the API key and add the identity header for the authentication method
    you selected:

    ```sh
    curl http://localhost:8787/v1/chat/completions \
      -H "authorization: Bearer $PUBLISHABLE_KEY" \
      -H "x-firebase-id-token: $FIREBASE_ID_TOKEN" \
      -H "content-type: application/json" \
      -d '{"model":"smart","messages":[{"role":"user","content":"Hello!"}]}'
    ```

    Add the verifier-specific header as well when app verification is enabled.
  </Step>
</Steps>
