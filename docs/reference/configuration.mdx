omni-model keeps its configuration in **PostgreSQL**, as an append-only series of revisions. The
environment variables on this page seed the first revision, on the first boot against an empty
database — after that the database is authoritative and the [admin API](/reference/admin-api)
changes configuration without a restart.

That means the same document shape is described twice on this page: once as environment variables
(what an automated deploy sets) and once as JSON (what the admin API stores). They are the same
document. It does not read YAML files, mounted configuration files, or an inline YAML variable.

<Note>
Editing an environment variable on a deployment that already has a stored revision changes nothing.
Change it through the admin API, or start from an empty database.
</Note>

<Info>
Keep credentials in your platform's secret store. Configuration values can reference them with
`${VAR}` interpolation, so a provider block can use `${OPENAI_API_KEY}` without copying the key
into a JSON configuration value.
</Info>

## Choose the right environment shape

Use the smallest shape that fits the change:

| Use case | Environment variable | Example |
| --- | --- | --- |
| Complete configuration | `OMNI_CONFIG_JSON` | A JSON object containing all top-level blocks. |
| Routing rules and their upstreams | `OMNI_ROUTING_JSON` | A JSON object with `rules` and `allowedModels`. |
| Rate-limit rules | `OMNI_RATE_LIMITS_JSON` | A JSON array of rules. |
| Authentication | `OMNI_SECURITY_JSON`, `OMNI_SECURITY_USER_AUTH_JSON` or `OMNI_SECURITY_APP_AUTH_JSON` | A JSON object per layer. |
| One upstream for everything | `OMNI_TARGET_*` | `OMNI_TARGET_TYPE=openai`. |
| One built-in verifier | `OMNI_SECURITY_<VERIFIER>_*` | `OMNI_SECURITY_FIREBASE_AUTH_ENABLED=true`. |
| One simple value | `OMNI_STORAGE_TYPE`, `OMNI_TARGET_TYPE`, `OMNI_SERVER_LOG_LEVEL`, or `OMNI_SECURITY_APP_AUTH_MODE` | `OMNI_STORAGE_TYPE=postgres`. |
| One deeply nested override | `OMNI__…` | `OMNI__ROUTING__RULES__0__TARGET__MODEL=gpt-4o-mini`. |

The precedence order is: `OMNI_CONFIG_JSON`, named JSON blocks, simple variables, then `OMNI__…`
paths. Later values override earlier values at the same path.

## Quick setup with named variables

Use named variables for the common one-upstream deployment. They avoid JSON and are the fastest way
to configure the container: setting any `OMNI_TARGET_*` variable seeds a single catch-all routing
rule (`id: "default"`, `when: "true"`) pointing at that upstream.

```sh
# Storage
OMNI_STORAGE_TYPE=postgres
OMNI_STORAGE_POSTGRES_URL='${DATABASE_URL}'

# The upstream everything is routed to
OMNI_TARGET_TYPE=openai
OMNI_TARGET_API_KEY='${OPENAI_API_KEY}'
OMNI_TARGET_MODEL=gpt-4o-mini

# One or more enabled authentication methods
OMNI_SECURITY_FIREBASE_AUTH_ENABLED=true
OMNI_SECURITY_FIREBASE_AUTH_PROJECT_ID=my-firebase-project
OMNI_SECURITY_FIREBASE_APPCHECK_ENABLED=true
OMNI_SECURITY_FIREBASE_APPCHECK_PROJECT_NUMBER=1234567890
OMNI_SECURITY_FIREBASE_APPCHECK_APP_ID=1:1234567890:ios:abc123
# Opt in only after clients send a fresh limited-use token per request.
OMNI_SECURITY_FIREBASE_APPCHECK_CONSUME=false

# More than one upstream, or a condition on a claim, is JSON: rules are ordered.
OMNI_ROUTING_RULES='[{"id":"smart","when":"request.model == \"smart\"","target":{"type":"openai","apiKey":"${OPENAI_API_KEY}","model":"gpt-4o-mini"}}]'
```

<Note>
`*_ENABLED` switches accept only `true` or `false`, and a verifier's companion variables do nothing
until its switch is `true`. Enabling two *user* methods is refused rather than resolved — whichever
won would own `user.id`, and that is whose token budget a request spends. App schemes layer: every
enabled one must accept by default; set `OMNI_SECURITY_APP_AUTH_MODE=any` when a client only ever
satisfies one of them, which is the case as soon as you serve more than one platform.
</Note>

## Client response privacy

The proxy returns only the OpenAI-compatible fields a client needs to use a result: completion or
stream identifiers generated by omni-model, the model alias the client requested, choices, message
content and tool calls, and finish reasons. It never returns upstream usage, token counts, costs,
provider names, service tiers, fingerprints, upstream identifiers, or provider-specific extra
fields. Token usage is retained privately so token-budget rate limits still work.
Provider error text is similarly replaced with a stable proxy error.

The same redaction applies to chat completions (including SSE), embeddings, and model ownership. The
client must not use `usage` for metering; enforce quotas on the proxy instead.

Use JSON blocks when you need a second named provider, more than one provider of the same type, or
full route/rate-limit objects. The [schema explorer](#environment-schema-explorer) below lists both
the easy variables and advanced fields.

## Full configuration in one variable

`OMNI_CONFIG_JSON` accepts every valid omni-model configuration field. Its value must be a JSON
object. This is useful when your infrastructure manager supports a single JSON secret or variable.

```sh
export OMNI_CONFIG_JSON='{
  "version": 1,
  "server": { "logLevel": "info" },
  "storage": { "type": "memory" },
  "security": {
    "userAuth": { "type": "jwt", "secret": "${OMNI_JWT_SECRET}", "algorithms": ["HS256"] }
  },
  "routing": {
    "rules": [
      {
        "id": "everything",
        "when": "true",
        "target": { "type": "openai", "apiKey": "${OPENAI_API_KEY}" }
      }
    ]
  }
}'
```

`OPENAI_API_KEY` and `OMNI_JWT_SECRET` remain independent environment variables. Bind them from
Secret Manager rather than placing their values inside `OMNI_CONFIG_JSON`.

## Composable JSON blocks

Named blocks make complex configuration easy to edit independently. They merge with each other and
with `OMNI_CONFIG_JSON`.

```sh
export OMNI_STORAGE_JSON='{"type":"postgres","url":"${DATABASE_URL}"}'

export OMNI_SECURITY_USER_AUTH_JSON='{"type":"firebase-auth","projectId":"${GOOGLE_CLOUD_PROJECT}"}'

export OMNI_SECURITY_APP_AUTH_JSON='{
  "mode": "all",
  "providers": [{"type":"firebase-app-check","appIds":["1:PROJECT_NUMBER:ios:APP_ID"]}]
}'

export OMNI_ROUTING_JSON='{
  "rules": [
    {
      "id": "fast",
      "when": "request.model == \"fast\"",
      "target": {
        "type": "openai-compatible",
        "baseUrl": "https://api.groq.com/openai/v1",
        "apiKey": "${GROQ_API_KEY}",
        "model": "llama-3.3-70b-versatile"
      }
    },
    {
      "id": "default",
      "when": "true",
      "target": {"type": "openai", "apiKey": "${OPENAI_API_KEY}"}
    }
  ]
}'
```

Available block variables are:

| Variable | Configuration path | JSON type |
| --- | --- | --- |
| `OMNI_CONFIG_JSON` | whole document | object |
| `OMNI_SERVER_JSON` | `server` | object |
| `OMNI_STORAGE_JSON` | `storage` | object |
| `OMNI_SECURITY_JSON` | `security` | object |
| `OMNI_SECURITY_USER_AUTH_JSON` | `security.userAuth` | object |
| `OMNI_SECURITY_APP_AUTH_JSON` | `security.appAuth` | object |
| `OMNI_RATE_LIMITS_JSON` | `rateLimits` | array |
| `OMNI_ROUTING_JSON` | `routing` | object |
| `OMNI_LOGGING_JSON` | `logging` | object |

## Granular `OMNI__…` paths

Use a double underscore to traverse configuration objects. Uppercase snake case converts to the
lower-camel-case property name. A numeric segment creates an array item.

```sh
# server.maxBodyBytes = 3000000
OMNI__SERVER__MAX_BODY_BYTES=3000000

# security.userAuth.type = "jwt"
OMNI__SECURITY__USER_AUTH__TYPE=jwt

# security.appAuth.providers[0].type = "apple-app-attest"
OMNI__SECURITY__APP_AUTH__PROVIDERS__0__TYPE=apple-app-attest

# routing.rules[0].target.apiKey = "${OPENAI_API_KEY}"
OMNI__ROUTING__RULES__0__TARGET__API_KEY='${OPENAI_API_KEY}'

# routing.rules[0].when = 'request.model == "smart"'
OMNI__ROUTING__RULES__0__WHEN='request.model == "smart"'
```

Values beginning with `{`, `[`, or `"` are parsed as JSON. Bare JSON numbers, `true`, `false`, and
`null` become their matching types. Other values remain strings. Use a JSON string such as `"123"`
when a string could otherwise be mistaken for a number.

For provider IDs or third-party option names that do not fit a shell-friendly path, set that object
as JSON instead:

```sh
OMNI_ROUTING_JSON='{
  "azure_openai-production": {
    "type": "openai-compatible",
    "baseUrl": "https://example.openai.azure.com/openai/v1",
    "apiKey": "${AZURE_OPENAI_API_KEY}"
  }
}'
OMNI_TARGET_TYPE=azure_openai-production
```

## Server

Use `OMNI_SERVER_JSON` for several values, or the individual aliases below.

| Path | Variable | Type | Default |
| --- | --- | --- | --- |
| `server.logLevel` | `OMNI_SERVER_LOG_LEVEL` (or legacy `OMNI_LOG_LEVEL`) | `debug` \| `info` \| `warn` \| `error` \| `silent` | `info` |
| `server.trustProxyHeaders` | `OMNI_SERVER_TRUST_PROXY_HEADERS` | boolean | `false` |
| `server.maxBodyBytes` | `OMNI_SERVER_MAX_BODY_BYTES` | positive integer | `131072` (128 KiB) |
| `server.cors` | `OMNI_SERVER_CORS` | JSON object | none |

Example browser CORS policy:

```sh
OMNI_SERVER_JSON='{
  "logLevel":"info",
  "cors":{
    "allowOrigins":["https://app.example.com"],
    "credentials":true,
    "maxAge":3600
  }
}'
```

Requests are capped at **128 KiB** by default, measured in UTF-8 bytes. The proxy checks both
`Content-Length` and streaming body bytes, returning `413 payload_too_large` without buffering an
oversized chunked request. Raise the limit deliberately for large multimodal or embedding inputs:

```sh
OMNI_SERVER_MAX_BODY_BYTES=524288
```

Set `trustProxyHeaders` only behind a reverse proxy or CDN that overwrites forwarding headers.

## Storage

`storage` controls rate-limit counters, token budgets, and Apple attestation state. Set
`OMNI_STORAGE_TYPE` first, then set only the option variables for that type. An option for the wrong
type is rejected during startup validation.

| Storage type | Setup variables | Platform / behavior |
| --- | --- | --- |
| `postgres` | `OMNI_STORAGE_TYPE=postgres`<br/>`OMNI_STORAGE_POSTGRES_URL=${DATABASE_URL}`<br/>`OMNI_STORAGE_POSTGRES_MIGRATE=true` | The production choice. Exact shared counters across every replica; required for App Attest when running more than one. `migrate` is optional (default `true`). |
| `memory` | `OMNI_STORAGE_TYPE=memory` | One process or local development. Nothing is shared across replicas and everything is lost on restart. |

`memory` is the default only when storage is omitted. Use `OMNI_STORAGE_JSON` for third-party
storage options not listed here.

## Security

Every HTTP proxy deployment needs at least one security provider. Every configured verifier must
accept by default; set `OMNI_SECURITY_APP_AUTH_MODE=any` explicitly to accept the first recognized valid
credential instead.

### Built-in verifier profiles

Set the profile's `*_ENABLED=true` switch, then provide its required fields. You may enable several
profiles; `OMNI_SECURITY_APP_AUTH_MODE` determines whether any or all of the app schemes must validate. Use
`OMNI_SECURITY_PUBLIC_PATHS='["/v1/models"]'` for paths that bypass authentication.

| Verifier | Enable and required configuration | Optional configuration |
| --- | --- | --- |
| Firebase Auth | `OMNI_SECURITY_FIREBASE_AUTH_ENABLED=true`<br/>`OMNI_SECURITY_FIREBASE_AUTH_PROJECT_ID=my-project` | `OMNI_SECURITY_FIREBASE_AUTH_HEADER`<br/>`OMNI_SECURITY_FIREBASE_AUTH_CLOCK_TOLERANCE_SECONDS` |
| Firebase App Check | `OMNI_SECURITY_FIREBASE_APPCHECK_ENABLED=true`<br/>`OMNI_SECURITY_FIREBASE_APPCHECK_PROJECT_NUMBER=1234567890` | `OMNI_SECURITY_FIREBASE_APPCHECK_APP_ID` (one)<br/>`OMNI_SECURITY_FIREBASE_APPCHECK_APP_IDS` (JSON array)<br/>`OMNI_SECURITY_FIREBASE_APPCHECK_HEADER`<br/>`OMNI_SECURITY_FIREBASE_APPCHECK_CONSUME` (default `false`)<br/>`OMNI_SECURITY_FIREBASE_APPCHECK_CLOCK_TOLERANCE_SECONDS`<br/><br/>`OMNI_GCP_PROJECT_NUMBER` is an alternative source for the project number. |
| JWT | `OMNI_SECURITY_JWT_ENABLED=true` plus exactly one of `OMNI_SECURITY_JWT_SECRET`, `OMNI_SECURITY_JWT_JWKS_URL`, or `OMNI_SECURITY_JWT_PUBLIC_KEY` | `OMNI_SECURITY_JWT_ALGORITHMS` (JSON array)<br/>`OMNI_SECURITY_JWT_ISSUER`<br/>`OMNI_SECURITY_JWT_AUDIENCE` (string or JSON array)<br/>`OMNI_SECURITY_JWT_HEADER`<br/>`OMNI_SECURITY_JWT_SCHEME` (`bearer` or `none`)<br/>`OMNI_SECURITY_JWT_USER_ID_CLAIM`<br/>`OMNI_SECURITY_JWT_DEVICE_ID_CLAIM`<br/>`OMNI_SECURITY_JWT_CLOCK_TOLERANCE_SECONDS` |
| Supabase | `OMNI_SECURITY_SUPABASE_ENABLED=true` plus one of `OMNI_SECURITY_SUPABASE_URL`, `OMNI_SECURITY_SUPABASE_JWT_SECRET`, or `OMNI_SECURITY_SUPABASE_JWKS_URL` | `OMNI_SECURITY_SUPABASE_ISSUER`<br/>`OMNI_SECURITY_SUPABASE_AUDIENCE` (string or JSON array)<br/>`OMNI_SECURITY_SUPABASE_HEADER`<br/>`OMNI_SECURITY_SUPABASE_CLOCK_TOLERANCE_SECONDS` |
| Apple App Attest | `OMNI_SECURITY_APP_ATTEST_ENABLED=true`<br/>`OMNI_SECURITY_APP_ATTEST_TEAM_ID`<br/>`OMNI_SECURITY_APP_ATTEST_BUNDLE_ID` | `OMNI_SECURITY_APP_ATTEST_ENVIRONMENT`<br/>`OMNI_SECURITY_APP_ATTEST_CHALLENGE_TTL`<br/>`OMNI_SECURITY_APP_ATTEST_ROOT_CA_PEM`<br/>`OMNI_SECURITY_APP_ATTEST_KEY_ID_HEADER`<br/>`OMNI_SECURITY_APP_ATTEST_ASSERTION_HEADER`<br/>`OMNI_SECURITY_APP_ATTEST_CHALLENGE_HEADER` |
| Apple DeviceCheck | `OMNI_SECURITY_DEVICE_CHECK_ENABLED=true`<br/>`OMNI_SECURITY_DEVICE_CHECK_TEAM_ID`<br/>`OMNI_SECURITY_DEVICE_CHECK_KEY_ID`<br/>`OMNI_SECURITY_DEVICE_CHECK_PRIVATE_KEY` | `OMNI_SECURITY_DEVICE_CHECK_DEVELOPMENT`<br/>`OMNI_SECURITY_DEVICE_CHECK_HEADER`<br/>`OMNI_SECURITY_DEVICE_CHECK_CACHE_TTL` |

Array and object variables use JSON: for example,
`OMNI_SECURITY_JWT_ALGORITHMS='["HS256"]'` and
`OMNI_SECURITY_FIREBASE_APPCHECK_APP_IDS='["1:123:ios:abc","1:123:android:def"]'`.
See the dedicated [security guides](/security/custom-jwt) for request headers and verification
behavior.

```sh
OMNI_SECURITY_JSON='{
  "mode":"all",
  "publicPaths":["/healthz"],
  "providers":[
    {"type":"firebase-app-check","appIds":["1:PROJECT_NUMBER:ios:APP_ID"]},
    {"type":"firebase-auth","projectId":"${GOOGLE_CLOUD_PROJECT}"}
  ]
}'
```

Supported provider types include `jwt`, `firebase-auth`, `firebase-app-check`, `supabase`,
`apple-app-attest`, and `apple-device-check`. Their fields are supplied directly in the JSON entry.
See the dedicated [security guides](/security/custom-jwt) for verifier-specific options and client
headers.

## Model routing

Routing is one ordered list of rules. Each rule is a condition and a **target**: which upstream,
with which credentials, as which model.

```json
{
  "routing": {
    "rules": [
      {
        "id": "pro-users",
        "when": "request.model == \"smart\" && has(user.claims.tier) && user.claims.tier == \"pro\"",
        "target": { "type": "anthropic", "apiKey": "${ANTHROPIC_API_KEY}", "model": "claude-sonnet-5" }
      },
      {
        "id": "everyone-else",
        "when": "true",
        "target": { "type": "openai", "apiKey": "${OPENAI_API_KEY}", "model": "gpt-4o-mini" }
      }
    ]
  }
}
```

Rules are evaluated top to bottom and the **first match wins**; nothing after it runs. There is no
separate default: a catch-all is a last rule with `when: "true"`. With no rule matching, the request
is a 404 `model_not_found`.

A target owns its credentials rather than referring to a named provider defined elsewhere. That is
deliberate — a reference can dangle, and "which key does this rule actually use" stopped being
answerable by reading the rule.

### Target fields

`type` is required and is one of `openai`, `openai-compatible`, `anthropic`, or `google`. The rest are
that provider's own options, validated by its schema — `GET /admin/api/meta` publishes them as JSON
Schema, which is how the dashboard renders a form per type.

| Provider type | Required | Optional |
| --- | --- | --- |
| `openai` | `apiKey` | `baseUrl`, `organization`, `headers`, `models`, `includeStreamUsage` |
| `openai-compatible` | `baseUrl` | `apiKey`, `organization`, `headers`, `models`, `includeStreamUsage` |
| `anthropic` | `apiKey` | `baseUrl`, `version`, `maxTokensDefault` |
| `google` | `apiKey` | `baseUrl` |

`model` is common to all of them: the upstream model to forward as. Omit it to pass the
client-requested model through unchanged, which is what a rule matching on `request.model` usually
wants.

### Rule fields

| Field | Type | Purpose |
| --- | --- | --- |
| `when` | string | CEL expression. Only a literal `true` counts as a match. |
| `target` | object | Where a match goes. See above. |
| `id` | string | Stable identity, used by logs and the admin API. Defaults to the rule's position, so a hand-written configuration need not invent one — but anything editing rules programmatically should set it, since a positional id changes meaning when rules are reordered. |
| `name` | string | Human label, shown as the route name in request logs. Defaults to `id`. |

### One upstream, the common case

Expressing "one provider, one key, send everything there" as a JSON array of rules would make the
simplest case the ugliest. These shortcuts build that catch-all rule instead:

| Variable | Applies to | Type / behavior |
| --- | --- | --- |
| `OMNI_TARGET_TYPE` | all | Required. Provider implementation type. |
| `OMNI_TARGET_MODEL` | all | Upstream model to forward as. |
| `OMNI_TARGET_API_KEY` | OpenAI, Anthropic, Google; optional for compatible | String or `${SECRET}` reference. |
| `OMNI_TARGET_BASE_URL` | all | URL. Required for `openai-compatible`; optional otherwise. |
| `OMNI_TARGET_HEADERS` | OpenAI / compatible | JSON object of extra upstream headers. |
| `OMNI_TARGET_MODELS` | OpenAI / compatible | JSON array used as a fallback model list. |
| `OMNI_TARGET_ORGANIZATION` | OpenAI / compatible | Optional OpenAI organization header. |
| `OMNI_TARGET_INCLUDE_STREAM_USAGE` | OpenAI / compatible | Boolean, default `true`. |
| `OMNI_TARGET_ANTHROPIC_VERSION` | Anthropic | String, default `2023-06-01`. |
| `OMNI_TARGET_ANTHROPIC_MAX_TOKENS_DEFAULT` | Anthropic | Positive integer, default `4096`. |

```sh
# OpenAI
OMNI_TARGET_TYPE=openai
OMNI_TARGET_API_KEY='${OPENAI_API_KEY}'

# Or an OpenAI-compatible endpoint such as Groq, OpenRouter, Together, or a local gateway.
OMNI_TARGET_TYPE=openai-compatible
OMNI_TARGET_BASE_URL=https://api.groq.com/openai/v1
OMNI_TARGET_API_KEY='${GROQ_API_KEY}'
```

They seed a rule with `id: "default"` and `when: "true"`. Anything more — several upstreams, or a
condition on a claim — is `OMNI_ROUTING_RULES`, or the [admin API](/reference/admin-api).

### Restricting what clients may ask for

| Variable | JSON type | Maps to |
| --- | --- | --- |
| `OMNI_ROUTING_ALLOWED_MODELS` | string array | `routing.allowedModels` |
| `OMNI_ROUTING_RULES` | array | `routing.rules` |

`allowedModels` is the client-facing catalogue: a request for anything else is a 404 before any rule
runs, and `GET /v1/models` lists exactly these. Leave it empty and every name is eligible for
routing, in which case `/v1/models` falls back to the distinct models the rules forward to.

Client-facing names need not match upstream names — that is what a target's `model` is for.

## Rate limits

`OMNI_RATE_LIMITS_JSON` (or the shorter alias `OMNI_RATE_LIMITS`) is an ordered JSON array. Every
rule needs a `name`, a key strategy, and at least one `requests` or `tokens` limit. When this
variable is omitted, omni-model limits each authenticated user to **30 requests per hour** and
**30,000 total tokens per day**.

```sh
OMNI_RATE_LIMITS_JSON='[
  {
    "name":"per-user-requests",
    "key":"user",
    "requests":{"limit":30,"window":"1h"}
  },
  {
    "name":"per-user-daily-tokens",
    "key":"user",
    "tokens":{"limit":30000,"window":"1d"}
  }
]'
```

`key` can be `user`, `device`, `client`, `ip`, `global`, or `expression`. Use `keyExpression` when
the key is `expression`; `client` keys per [write key](/reference/write-keys). Durations are `500ms`,
`30s`, `5m`, `1h`, or `1d`.

Give every rule a stable `id`. Counters are namespaced by `id` (falling back to `name`), so a rule
identified only by its display name silently resets its counters the first time it is renamed.

## Environment schema explorer

This is the canonical configuration object after omni-model merges your environment variables. Use
it as a JSON-schema-style map when an easy variable does not cover an option. Each component validates
its own options at startup, so unsupported fields fail before the service accepts traffic.

| Root field | JSON type | Default | Notes |
| --- | --- | --- | --- |
| `version` | literal `1` | `1` | Compatibility marker. |
| `server` | object | `{ logLevel: "info", trustProxyHeaders: false, maxBodyBytes: 131072 }` | HTTP and logging behavior. |
| `storage` | object | `{ type: "memory" }` | Selects a storage backend and its options. |
| `security` | object | `{ publicPaths: [], appAuth: { mode: "all", providers: [] } }` | `userAuth` has no default and is required for an HTTP proxy. |
| `rateLimits` | array | `[{ per-user-daily-tokens: 30000/1d }]` | Per-user token budgets. |
| `routing` | object | `{ allowedModels: [], rules: [] }` | Restricts client model names and chooses an upstream. |

### `server` object

| Field | Type | Default |
| --- | --- | --- |
| `logLevel` | `debug` \| `info` \| `warn` \| `error` \| `silent` | `info` |
| `trustProxyHeaders` | boolean | `false` |
| `maxBodyBytes` | positive integer | `131072` (128 KiB) |
| `cors.allowOrigins` | string array | `["*"]` |
| `cors.allowMethods`, `cors.allowHeaders`, `cors.exposeHeaders` | string arrays | omitted |
| `cors.maxAge` | positive integer seconds | omitted |
| `cors.credentials` | boolean | omitted |

### `security` object

Authentication is two layers. **Layer 1 — `userAuth`** answers *which user*: exactly one method,
and required, because token budgets are counted per user and a request that does not say who it is
has nothing to spend. **Layer 2 — `appAuth`** answers *which app*: optional, and any number, since
one attestation scheme per platform is normal.

| Field | Type | Default | Constraint |
| --- | --- | --- | --- |
| `userAuth` | object | none | One of `firebase-auth`, `supabase`, `jwt`. A bundle refuses to build without it, so `/v1` answers 503 rather than serving unauthenticated traffic. |
| `appAuth.mode` | `any` \| `all` | `all` | `all` requires every configured scheme — right for one platform layering two. `any` takes the first that accepts — right for several platforms, since a client can only satisfy its own. |
| `appAuth.providers` | array | `[]` | Any of `firebase-app-check`, `apple-app-attest`, `apple-device-check`. |
| `publicPaths` | string array | `[]` | Exact paths or a trailing `*` prefix. |
| `requireWriteKey` | boolean | `false` | Demand `x-omni-key` on every `/v1/*` request. |

A verifier configured in the wrong layer is refused by name, with the field it belongs in — putting
App Attest in `userAuth` is one field away from correct, and attesting an app is not the same as
knowing who is calling.

```yaml
security:
  userAuth:
    type: jwt
    secret: ${OMNI_JWT_SECRET}
    algorithms: [HS256]
  appAuth:
    mode: any
    providers:
      - type: apple-app-attest
        teamId: ABCDE12345
        bundleId: com.example.app
      - type: firebase-app-check
        projectNumber: "1234567890"
```

### `rateLimits[]` object

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string | one of id/name | Stable counter keyspace. Defaults to `name` — set it explicitly for any rule that can be renamed. |
| `name` | string | one of id/name | Display name, shown in rate-limit headers/logs. Defaults to `id`. |
| `when` | CEL string | no | Applies only when it evaluates to `true`. Omitted means every request — a baseline, not a fallback: every matching rule is enforced. |
| `tokens` | `{ limit: positive integer, window: duration }` | yes | Prompt + completion token budget, per user. |

Every budget is counted **per user**, and tokens are the only axis. There is no request-count
window: tokens are what a request costs, so that is what these rules protect. A flood of requests
that spend no tokens is not limited here — see [concurrency](#concurrency) for the bound that is.

### `routing` object

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `allowedModels` | string array | `[]` | Exact client model names allowed for chat and embeddings. When non-empty, `/v1/models` returns this list only. |
| `rules` | array of `{ when, target, id?, name? }` | `[]` | Ordered; first match wins. A catch-all is `when: "true"`. |

See [Model routing](/model-routing/routing) for the CEL request context and a full routing example.

## Bootstrap variables

These four are the only variables the database cannot hold, because they are what the container
needs before it can read the database.

| Variable | Purpose |
| --- | --- |
| `OMNI_STORAGE_TYPE` + `OMNI_STORAGE_POSTGRES_URL` | Where everything lives. Storage cannot be changed by saving a revision. |
| `OMNI_ENCRYPTION_KEY` | Base64 32-byte master key for [encrypted secrets](/reference/admin-api#secrets). `OMNI_ENCRYPTION_KEY_PREVIOUS` is accepted for decryption during a rotation. |
| `OMNI_ADMIN_SECRET` | Signs operator sessions, minimum 32 characters. **Without it there is no admin API at all.** |
| `PORT`, `OMNI_LOG_LEVEL` | Process-level settings. |

Optional, for a dashboard hosted separately from the proxy:

| Variable | Purpose |
| --- | --- |
| `OMNI_ADMIN_BASE_URL` | The proxy's public origin, so session cookies are issued for the right host behind a reverse proxy. |
| `OMNI_ADMIN_ALLOWED_ORIGINS` | Comma-separated origins allowed to send credentialed admin requests. |

```sh
docker run -p 8787:8787 \
  -e OMNI_STORAGE_TYPE=postgres \
  -e OMNI_STORAGE_POSTGRES_URL="$DATABASE_URL" \
  -e OMNI_ENCRYPTION_KEY="$(openssl rand -base64 32)" \
  -e OMNI_ADMIN_SECRET="$(openssl rand -base64 32)" \
  ghcr.io/tiepvuvan/omni-model
```

<Warning>
Keep `OMNI_ENCRYPTION_KEY` for as long as the database lives. It decrypts every stored credential;
lose it and every secret has to be re-entered.
</Warning>

## Validation and interpolation

Every configuration — seeded, or saved through the admin API — is validated before it is applied.
Unknown top-level fields, invalid JSON, missing secrets, unknown providers, invalid CEL, or invalid
component options are rejected with the same message in both cases.

A rejected revision never takes a running proxy down: the previous configuration keeps serving and
the error comes back to whoever tried to save it. A rejected *seed* leaves the proxy unconfigured,
answering 503 on `/v1` and explaining why on `/readyz`.

String values support:

```text
${NAME}             required environment value
${NAME:-fallback}   environment value with a fallback
$${NAME}            a literal ${NAME}
```

References are resolved when a revision is applied, not when it is stored, so a stored revision never
contains a resolved credential. For credentials that have no environment variable to point at, use
[`{"$secret": "…"}` references](/reference/admin-api#secrets) instead.
