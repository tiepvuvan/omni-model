---
title: AWS Cognito
description: Authenticate users with Amazon Cognito user-pool access or ID tokens.
---

The `aws-cognito` verifier authenticates JWTs issued by an Amazon Cognito
**user pool**. It pins the pool issuer, verifies RS256 signatures against the
pool's rotating JWKS, validates expiration, checks `token_use`, and applies
Cognito's distinct app-client rule:

- Access tokens identify the app client in `client_id`.
- ID tokens identify the app client in `aud`.

This verifier is for user pools, not Cognito identity-pool credentials.

## Configuration

For an API, prefer access tokens and require the scopes that authorize model
calls:

```yaml
security:
  userAuth:
    type: aws-cognito
    region: us-east-1
    userPoolId: us-east-1_AbCdEf123
    clientIds:
      - 4exampleclientid
    tokenUse: access
    requiredScopes:
      - models:invoke
```

<ParamField path="region" type="string" required>
AWS region containing the user pool, such as `us-east-1`.
</ParamField>
<ParamField path="userPoolId" type="string" required>
User pool ID from the Cognito console. Its prefix must match `region`.
</ParamField>
<ParamField path="clientIds" type="string[]" required>
Allowed user-pool app client IDs. Configure every web or mobile app that may
call this proxy.
</ParamField>
<ParamField path="tokenUse" type="access | id | either" default="access">
Accepted Cognito token kind. Access tokens are intended to authorize APIs. Use
`id` only when you deliberately authenticate with profile-bearing ID tokens;
`either` accepts both while retaining the correct client check for each.
</ParamField>
<ParamField path="requiredScopes" type="string[]">
OAuth scopes every access token must contain. This cannot be configured when
`tokenUse` is `id`.
</ParamField>
<ParamField path="header" type="string" default="x-cognito-id-token">
Header carrying the raw user-pool token.
</ParamField>
<ParamField path="scheme" type="bearer | none" default="none">
How to extract the token from the configured header.
</ParamField>
<ParamField path="clockToleranceSeconds" type="integer" default="60">
Allowed clock skew for token timestamps.
</ParamField>

The named environment profile is equivalent:

```sh
export OMNI_SECURITY_AWS_COGNITO_ENABLED=true
export OMNI_SECURITY_AWS_COGNITO_REGION=us-east-1
export OMNI_SECURITY_AWS_COGNITO_USER_POOL_ID=us-east-1_AbCdEf123
export OMNI_SECURITY_AWS_COGNITO_CLIENT_IDS='["4exampleclientid"]'
export OMNI_SECURITY_AWS_COGNITO_TOKEN_USE=access
export OMNI_SECURITY_AWS_COGNITO_REQUIRED_SCOPES='["models:invoke"]'
```

The proxy needs no AWS credential to verify tokens. Cognito publishes the user
pool's public signing keys at its well-known JWKS endpoint.

## Send an access token

With Amplify, refresh the auth session as usual and send the access token:

```typescript
import { fetchAuthSession } from "aws-amplify/auth";

const session = await fetchAuthSession();
const token = session.tokens?.accessToken.toString();
if (!token) throw new Error("The user is not signed in");

const response = await fetch("https://proxy.example.com/v1/chat/completions", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${publishableKey}`,
    "Content-Type": "application/json",
    "X-Cognito-ID-Token": token,
  },
  body: JSON.stringify({
    model: "smart",
    messages: [{ role: "user", content: "Hello" }],
  }),
});
```

The custom scope must be enabled on the app client and granted to the token by
your Cognito resource server configuration.

## Verified identity and failures

The verified `sub` becomes `user.id`. Cognito claims such as `username`,
`cognito:groups`, `scope`, and custom attributes remain available under
`user.claims`.

An invalid signature, pool issuer, token kind, app client, scope, expiration, or
subject returns `401`. A failure to retrieve or parse the Cognito JWKS returns
`503 verification_unavailable`.

See AWS's official [JWT verification guide](https://docs.aws.amazon.com/cognito/latest/developerguide/amazon-cognito-user-pools-using-tokens-verifying-a-jwt.html)
and [access-token reference](https://docs.aws.amazon.com/cognito/latest/developerguide/amazon-cognito-user-pools-using-the-access-token.html)
for user-pool and resource-server setup.
